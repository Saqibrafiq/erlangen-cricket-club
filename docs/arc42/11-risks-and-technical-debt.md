# 11. Risks & Technical Debt

## 11.1 Risks

| ID   | Risk                                                                                                      | Probability | Impact | Mitigation                                                                                                                                                                             |
| ---- | --------------------------------------------------------------------------------------------------------- | ----------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-1  | Free-tier limits change or are exceeded (Vercel, Neon, Blob)                                              | Medium      | High   | Static rendering/ISR to minimise function and DB usage; image optimisation; monitor usage                                                                                              |
| R-2  | Neon scale-to-zero cold starts slow the first admin request                                               | High        | Low    | Public pages are static; only admin and revalidation hit the DB                                                                                                                        |
| R-3  | Brand colours are provisional (not yet derived from the club logo)                                        | High        | Medium | Colours exist only as tokens in `globals.css`; replace values and re-check contrast                                                                                                    |
| R-4  | Player personal data published without consent                                                            | Low         | High   | Consent flag and note on player records; read access and public queries both filter on it ([ADR-0009](09-architecture-decisions/0009-player-profiles-require-recorded-consent.md))     |
| R-5  | Single maintainer (bus factor 1)                                                                          | High        | Medium | arc42 docs, ADRs, enforced conventions, CI                                                                                                                                             |
| R-6  | Results on the website drift from the league's CricClubs records                                          | Medium      | Medium | Editors enter results after each match; derived margins expose typos; revisit if the league offers an export ([ADR-0003](09-architecture-decisions/0003-own-match-data-in-payload.md)) |
| R-7  | Builds fail when the database is unreachable (pages prerender from it)                                    | Low         | High   | Neon availability; CI exercises migrate + seed + build on every PR                                                                                                                     |
| R-9  | Standings on the website lag behind the published tables (editor forgets to copy the table after a round) | Medium      | Medium | CMS field description; copy the table with the round's results ([ADR-0006](09-architecture-decisions/0006-standings-from-published-tables.md))                                         |
| R-10 | Contact messages go unnoticed (stored in the admin, no notification)                                      | Medium      | Medium | Board routine to check the admin; add email notification if needed ([ADR-0007](09-architecture-decisions/0007-contact-messages-stored-in-cms.md))                                      |
| R-8  | Site goes live without a complete Impressum / Datenschutzerklärung (legal requirement in Germany)         | Medium      | High   | Pages show a "being prepared" notice until editors fill the Payload globals; **launch blocker** — fill in before switching DNS                                                         |
